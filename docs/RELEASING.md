# Releasing CV-Embed

## What has to be true before a release

Every gate in `npm run build` and both test suites has to be green. The order
matters because later gates assume earlier ones:

```bash
npm run lint          # ESLint over src, sdk, scripts, tests
npm run build         # tsc -b, vite build, then two artifact checks
npm run test:unit     # vitest, including the bridge protocol schemas
npm run test:e2e      # Playwright: Chromium desktop/mobile + Firefox
npm audit --omit=dev
git diff --check
```

`npm run build` is not just a bundler step. After `vite build` it runs two
checks that fail the build:

- `scripts/check-production-build.mjs` fails if the production entry imports the
  PDF renderer eagerly. The first visit must not pay for it.
- `scripts/build-sdk.mjs --check` fails if `public/sdk.js` differs from a fresh
  build of `sdk/`, or if the generated global no longer exposes `render`,
  `version`, or `protocolVersion`.

CI runs the same commands, in that order, on every push and pull request.

## Versioning

Two independent versions, both defined in `sdk/protocol.ts`:

| Constant | Meaning | Bump when |
| --- | --- | --- |
| `SDK_VERSION` | the SDK package | any SDK release, breaking or not. Semver. |
| `PROTOCOL_VERSION` | the wire format | any breaking change to a message contract |

`package.json` is versioned with `SDK_VERSION`. Keep them in step when you
release: they describe the same artifact from two angles.

### What is a breaking protocol change

Bump `PROTOCOL_VERSION` when you change any of:

- an envelope field name, or add one a receiver would treat as required
- a message or command name, or remove one
- a payload field's name, type, or whether it is required
- which direction a message travels

Not breaking:

- adding an **optional** payload field
- adding a new event or command, because receivers drop unknown names
- wording changes inside a `message` string

### What happens on a version mismatch

Deliberately fail closed, in both directions:

- The SDK drops any event whose `version` is not `PROTOCOL_VERSION`.
- The embed drops any command whose `version` is not `PROTOCOL_VERSION` and
  replies with an `error` event, code `unsupported-protocol`, `fatal: true`.

So a host on an old SDK and a frame on a new protocol find out immediately
instead of half-working. There is no compatibility shim and no negotiation.
Adding one would mean a compatibility matrix, which this project does not have a
reason to carry.

## How to change the protocol

1. Edit the schemas and types in `sdk/protocol.ts`. That file is the contract;
   both ends read it.
2. Update `docs/SDK_PROTOCOL.md` in the same change. It is generated by hand, so
   it will drift unless someone keeps it honest.
3. If the change is breaking, bump `PROTOCOL_VERSION` and `SDK_VERSION` to a
   major, and note the migration in the release notes.
4. If the change is additive, bump only the minor or patch.
5. Run `npm run build:sdk` and commit the regenerated `public/sdk.js`. The build
   fails if you forget.
6. Add coverage in `sdk/protocol.test.ts` and `tests/e2e/sdk-contract.spec.ts`.
   Both drive the real artifact, not a copy of the behaviour.

## Artifact: `public/sdk.js`

Checked into the repository and built from `sdk/index.ts`, so it is regenerated
rather than edited. It is built unminified on purpose: a host debugging a
message problem can read it. It costs about 28 kB gzipped, most of which is
Zod, which validates every message at the boundary.

If you ever minify it, measure the host's first paint before and after rather
than assuming smaller is better.

## Release checklist

- [ ] `npm run lint`, `npm run build`, `npm run test:unit`, `npm run test:e2e`
- [ ] `npm audit --omit=dev` reports no high or critical advisories
- [ ] `npm run measure` run against the production build; numbers recorded in
      `docs/PERFORMANCE.md` if they moved
- [ ] `public/sdk.js` regenerated and committed
- [ ] `docs/SDK_PROTOCOL.md` matches the schemas
- [ ] `docs/CV_EMBED_AUDIT_RESULTS.md` updated if behaviour changed
- [ ] `PROTOCOL_VERSION` bumped if, and only if, the wire format changed
